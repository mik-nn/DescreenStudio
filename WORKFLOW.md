# Workflow — как ведётся работа над проектом

## Источники истины

| Документ | Что фиксирует |
|---|---|
| `ImplementationPlan.md` | Целевая архитектура, этапы, критерии приёмки. Меняется только через запись в `JOURNAL.md`. |
| `TASKS.md` | Текущий пул задач и их статусы. |
| `JOURNAL.md` | Хронология решений, экспериментов, метрик. |
| `AGENTS.md` | Правила и контекст для агентов. |

## Жизненный цикл задачи

```
TODO → IN PROGRESS → VERIFY → DONE
         │              │
         └── BLOCKED ───┘ (причина в JOURNAL)
```

- **TODO** — задача описана, критерий готовности понятен.
- **IN PROGRESS** — не более одной задачи за раз.
- **VERIFY** — код/артефакт готов, идёт проверка (тесты, визуальный контроль, метрики).
- **DONE** — проверено, метрики записаны в JOURNAL.

## Сессия работы

1. **Старт:** прочитать `TASKS.md` + последние 3–5 записей `JOURNAL.md`.
2. **Взять задачу:** перевести в IN PROGRESS в `TASKS.md`.
3. **Работа:** промежуточные решения и находки — сразу в `JOURNAL.md` (дата, контекст, решение, почему).
4. **Финиш:** задача → VERIFY → DONE; результаты и метрики — в `JOURNAL.md`.

## Формат записи в JOURNAL.md

```markdown
## YYYY-MM-DD — Короткий заголовок

**Контекст:** какая задача/проблема.
**Решение/Результат:** что сделано, ключевые цифры/параметры.
**Артефакты:** пути к файлам/моделям.
**Следующий шаг:** (опционально).
```

## Правила принятия решений

- Изменение критериев приёмки, источников данных, архитектуры модели → **сначала** запись-предложение в `JOURNAL.md`, потом правка `ImplementationPlan.md`.
- Эксперименты без результата (отрицательные) тоже фиксируются — чтобы не повторять.
- Любой сгенерированный датасет/модель → манифест с параметрами + seed рядом с артефактом.
