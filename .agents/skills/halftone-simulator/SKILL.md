# Halftone Simulator — правила работы

## Архитектура (двухкаскадная, обязательная)

```
GT (чистое изображение)
  → Каскад 1 «Печать»: RGB→CMYK → AM/FM растр @ печатном DPI (2400–4800) → dot gain → наложение красок → текстура бумаги
  → Каскад 2 «Сканер»: поворот 0.1–2° → PSF (Gaussian σ 0.3–1.2) → ресемплинг до 300/600 DPI → шумы Гаусс/Пуассон → пыль
```

**Главный инвариант:** муар возникает только как алиасинг при ресемплинге каскада 2. Запрещено рисовать муар постфактум или генерировать растр сразу в разрешении скана — спектр будет нефизичным, сеть не обобщится на реальные сканы.

## Параметры (всё — через конфиг, никаких констант в коде)

- AM: LPI 85–175; углы C15°/M75°/Y0°/K45° (варьировать ±3°); форма точки: круг/эллипс/квадрат; TVI (dot gain) 10–25%.
- FM: blue noise / error diffusion.
- Критический режим для тестов: 150 LPI @ 300 DPI (период растра = 2 px, граница Найквиста).

## Код

- Расположение: `ml/simulator/`. Python, типизация, dataclass-конфиги (`PrintConfig`, `ScanConfig`).
- Явный `seed` в каждом вызове генерации. Каждый сгенерированный датасет → JSON-манифест с полными параметрами каждого патча.
- Скорость генерации важна: тяжёлые операции — NumPy/PyTorch, при необходимости GPU.

## Проверка перед DONE (задачи 1.3/1.4)

1. Визуальный контроль: растровая точка видна в лупу, муар появляется при повороте — похоже на реальный скан.
2. Спектральный контроль: 2D FFT синтетики сопоставим с референсами из `knowledge/reference-spectra.md` (пики растра на ожидаемых частотах, муарные биения при повороте).
3. Запись результатов в `JOURNAL.md`.
