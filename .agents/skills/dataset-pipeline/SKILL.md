# Dataset Pipeline — правила работы

## Источники GT (только коммерчески чистые)

| Источник | Контент | Лицензия | Проверено |
|---|---|---|---|
| Unsplash Lite (25k) | фото | Unsplash License — коммерч. OK | да |
| DIV2K | фото 2K | исследовательская — уточнить при коммерч. использовании | частично |
| Собственный рендер (Gutenberg/Wikipedia → HTML/LaTeX → 600 DPI) | текст, документы | полностью наша | да |

**Запрещено:** DESCAN-18K (CC BY-NC-SA + офисные МФУ), готовые сканы гравюр из public domain (уже содержат печатный растр).

## Требования к GT

- Разрешение ≥ 2048×2048, без сжатия (PNG/TIFF). Рендер документов — 600 DPI, кегль от 4 pt.
- Перед попаданием в набор GT изображение проверяется на отсутствие собственной периодики (детектор пиков FFT — см. skill descan-eval): «грязный» GT отбраковывается.

## Сборка датасета

- Расположение: `Data/synth/` (train/val), GT — `Data/gt/`.
- Патчи 512×512; 10 000 train / 1 000 val; пересечений между train и val источниками быть не должно (сплит по исходным изображениям, не по патчам).
- Распределение по контенту: ~50% фото / ~30% документы / ~20% смешанное — задавать конфигом.
- Каждый датасет → `manifest.json`: версия генератора, seed, параметры растра/сканера каждого патча, хэши источников.

## Проверка перед DONE

1. Манифест существует и валиден; `seed` воспроизводит датасет бит-в-бит.
2. Спот-проверка 20 случайных патчей глазами + спектр.
3. Запись в `JOURNAL.md` (объём, параметры, путь).
