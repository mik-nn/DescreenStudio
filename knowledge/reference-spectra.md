# Reference Spectra — измеренные спектры реальных сканов

Метод: `ml/simulator/analyze_refs.py` — чтение TIFF 1024×1024 из zip в память (без распаковки), 2D FFT, топ-10 пиков, HF-пол (медиана при r>0.45). Выборка: 40 Valid + 40 Test, seed 0. Сырые данные: `ml/simulator/_refs/refs.json`. Train.zip не тронут.

## Valid (scanner3 Canon iR-ADV 6265, scanner4 Plustek OpticBook 4800)

- Доминирующие пики: r = 0.01–0.036 (медиана топ-1 0.019), xmean 300–800 — энергия вёрстки (текстовые блоки, фото), не растр.
- Пиков растра у Найквиста **нет**. 3/40 кадров с пиками r>0.15 — все строго ±90° (r 0.157–0.18, xmean 130–195): горизонтальные линейки/базовые линии текста (период ~5.5 px), не растр.
- HF-пол: медиана 0.071, p90 0.118 — тихие сканы.

## Test (scanner1 Fuji Xerox C2060, scanner2 Canon imagePRESS C650)

- Та же картина: топ-пики r 0.01–0.049 (медиана 0.023) — контент. 4/40 с пиками r>0.15, все ±90° (текстовые линейки).
- HF-пол: медиана 0.154, p90 0.261 — заметно шумнее Valid (другие движки обработки).

## Выводы для симулятора

1. **Растровых пиков в DESCAN-сканax нет вообще** (0/80): офисные МФУ давят растр прошивкой либо линиатура уходит за Найквист. Это прямое подтверждение решения JOURNAL 2026-09-08: датасет не отражает продакшн-вход (скан журнального растра 85–175 LPI, где пики обязаны быть — как в нашей синтетике: 0.443 цикл/px при magazine 133 LPI @ 300 DPI).
2. Дефолты симулятора **не меняем**: они выведены из физики печати и плана, а не из этих сканов. Нижние концы диапазонов шумов (Гаусс 0.004, Пуассон 120) покрывают тихие офисные сканы; верхние — зернистую продукцию.
3. Побочный ориентир: реальные сканы документов дают сильные горизонтальные пики r≈0.18 (±90°) от строк текста — наш документный GT (задача 1.2) даст то же самое естественным путём; при калибровке 1.6 не принимать их за растр.
4. HF-пол нашей фото-синтетики (0.40) выше DESCAN — но метрика смешана с гармониками растра у Найквиста; как мера чистого шума непригодна, только ориентация.
